# 远程基础服务

本文说明远程部署的配置边界，不记录实际服务器地址、个人路径或部署凭据。当前本地开发方式见 [本地基础服务](local-infra.md)。

## 配置与隔离

- `infra/` 提供 PostgreSQL 与 Redis 的基础服务配置，业务库、测试库及缓存应与其他项目隔离。
- 服务器地址、SSH 身份文件和连接凭据由部署环境提供，不写入公开文档。
- 应用连接配置保存在被 Git 忽略的 `services/api/.env` 中；不要提交该文件、SSH 私钥或服务器凭据文件。
- 数据库连接应通过受限网络或 SSH 隧道提供给应用；具体访问控制由部署环境维护。

## 运维

- 使用 Docker Compose 查看服务状态与日志，使用 `/api/v1/health/ready` 检查数据库及 Redis 连通性。
- 更新服务时保留持久化数据卷；修改数据库密码时，同步更新数据库账号和应用连接配置。
- 备份应保存到独立位置，并在专用空库中验证恢复，避免覆盖业务数据。
- 本地与远程数据不会自动同步，切换前须明确数据来源、同步方向并完成备份。
