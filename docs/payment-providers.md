# 支付供应商接入

后台入口：`/admin/orders?tab=config`。超级管理员维护供应商实例和积分套餐，管理员查看订单与统计，用户在 `/account/credits` 选择套餐和支付渠道。同一种供应商可创建多个商户实例，按排序值展示。

## 支持范围

| 供应商 | 当前支付方式 | 套餐币种 | 必填商户配置（另需公网 HTTPS 域名） |
| --- | --- | --- | --- |
| 易支付 | 支付宝、微信，跳转收银台 | CNY | 网关地址、PID、商户密钥 |
| 支付宝直连 | 电脑网站支付，RSA2 | CNY | 环境、App ID、商户 UID、应用私钥、支付宝公钥 |
| 微信支付 | Native 扫码，API v3 公钥模式 | CNY | App ID、商户号、商户证书序列号、商户 API 私钥、API v3 密钥、微信支付公钥 ID 和公钥 |
| Stripe | Checkout 银行卡支付 | USD、EUR、CNY | Secret Key、Webhook Secret |
| Airwallex | 一次性 Payment Link 托管收银台 | USD、EUR、CNY | 环境、Client ID、Account ID、API Key、Webhook Secret |

可用币种还受商户账户和上游开通能力限制。易支付使用兼容的 MD5 v1 `submit.php` 协议；不包含各网关的私有扩展。支付宝使用公钥模式，不包含证书模式；微信不包含 JSAPI、小程序或服务商代收。Airwallex 收银台内可用付款方式由商户侧开通情况决定。

## 配置步骤

1. 应用数据库迁移：在 `services/api` 运行 `uv run alembic upgrade head`，包括 `0008_payment_providers`。
2. 使用超级管理员打开供应商配置，选择类型，填写名称、支付方式、排序和商户参数。未填齐时可以保存为停用草稿；启用时会检查必填项和密钥格式。
3. 填写站点公网 HTTPS 域名，例如 `https://pay.example.com`，不带路径。该域名同时用于支付返回页面和通知地址，必须能访问本站页面及 API。
4. 保存后，复制页面显示的专属通知地址到支付平台。地址为 `/api/v1/billing/providers/{供应商 UUID}/webhook`。易支付、支付宝和微信下单时也会传入此地址。
5. 配置套餐并启用供应商。金额使用最小货币单位，例如 `500` 表示 5 元或 5 美元。只展示与套餐币种匹配的支付渠道。
6. 在对应平台的测试环境完成联调；微信 Native 和实际易支付网关是否提供测试能力取决于平台。正式启用前核对商户号、回调、币种和到账记录。

回调必须保留原始请求体和签名请求头，无需登录 Cookie。反向代理应允许外部 POST；易支付也接受 GET 通知。其他渠道仅接受 POST。

| 供应商 | 订阅或处理的成功事件 |
| --- | --- |
| 易支付 | `TRADE_SUCCESS` |
| 支付宝 | `TRADE_SUCCESS`、`TRADE_FINISHED` |
| 微信 | `TRANSACTION.SUCCESS` |
| Stripe | `checkout.session.completed`、`checkout.session.async_payment_succeeded`；另订阅 `checkout.session.async_payment_failed`、`checkout.session.expired` |
| Airwallex | `payment_link.paid` |

Stripe 在非生产环境只允许启用测试密钥。支付宝和 Airwallex 可选择 sandbox/live。微信 API v3 密钥必须为 32 字节；RSA 密钥至少 2048 位。配置完整仅表示本地校验通过，不表示已经验证商户连通性。

## 密钥和订单安全

商户配置加密存储。API 不返回密钥，页面只显示是否已配置；留空保留原密钥。修改使用 revision 防止覆盖其他管理员的更新，审计只记字段名。

实例一旦产生订单，商户配置即锁定，以保留旧订单的验签依据。更换密钥、商户或回调域名时，新建实例并停用旧实例。停用阻止新订单，旧实例仍接收回调；有订单的实例不可删除。无订单的草稿可以删除。

订单保存套餐、价格、积分和供应商快照。只有经过签名校验并匹配商户、订单、金额、币种和支付会话的通知才能入账。余额与流水在同一数据库事务中更新，重复及并发回调只入账一次；已支付订单不会被迟到的失败通知覆盖。浏览器返回、二维码显示和手动查询都不能确认支付。

微信二维码在浏览器本地生成，无需第三方二维码服务。用户可以从待支付订单继续打开已有收银台；页面轮询本站订单状态，入账后刷新余额。超过轮询次数后可手动查询。

## 兼容与边界

原有 Stripe 配置保留在折叠的兼容入口，旧订单继续使用 `/api/v1/billing/webhook`；新的 Stripe 实例使用各自的专属回调。不要混用两个入口的 Webhook Secret。旧配置已就绪时，仍可作为独立渠道展示。

本次集成用于一次性积分充值。订阅、自动退款、争议扣回、发票、自动对账和回调补偿任务未实现。收到延迟但有效的付款通知仍可入账；长期待支付订单需要到支付平台核实，不能依据浏览器返回地址补发积分。

自动化测试使用模拟上游响应和签名通知，覆盖五种渠道、权限隔离、密钥脱敏、金额篡改、无效签名、重复与并发通知、跨订单交易号复用等情况。尚未使用真实商户凭据完成测试环境或正式环境收款联调。
