# 图片生成工具

入口 `/tools/image-generate`。后台模型账号配置兼容 Images API 的地址和密钥，勾选图片生成能力并选择模型；将账号加入任意分组，再把工具绑定到该分组。分组只聚合账号，实际能力和模型由账号提供。

## 运行

在 `services/api` 执行迁移后启动 API，并独立运行 `python -m tooldawn.image_worker`。Windows 本地 `scripts/dev.ps1` 已一并启动 Worker；线上也需要用进程管理器保持 Worker 运行。新环境需按 README 执行目录种子初始化。

- 文生图通过 `/v1/images/generations`；图生图通过 multipart `/v1/images/edits`。一次一张 PNG，可选择 1024×1024、1536×1024、1024×1536。账号分别声明 `image_generate`、`image_edit` 能力及模型；工具仍绑定一个聚合账号组。实际支持范围由接入账号决定。
- 质量 low／medium／high 对应基础积分的 1／2／4 倍，由服务端计算。透明背景通过 `background=transparent` 请求，并检查输出确实包含透明像素；不满足时按失败退分。
- 参考图仅接受静态 PNG／JPEG／WebP，最大 8 MiB、2000 万像素，服务端纠正方向并缩小至最长边 2048、剥离元数据。参考图加密暂存一小时，每用户最多八张；任务入队时复制到加密载荷，之后移除参考图不会破坏已排队任务。
- API 在同一个数据库事务内创建运行记录、加密任务输入并预扣积分。请求 UUID 和内容指纹保证幂等。现阶段与文字工具共享使用记录、积分流水和统计。
- Worker 通过 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取任务，可启动多个进程。每次最多尝试三个符合能力的账号；可重试错误触发共享冷却，非重试错误停止。
- 单账号最长 180 秒，执行总上限 550 秒，任务自创建起 660 秒过期。Worker 恢复时将过期任务标记失败并退分；已领取但中断的上游请求不自动重放。退款通过用户行锁和流水幂等键确保一次。
- 任务输入仅加密短暂保存，完成或过期后清空。上游错误正文、密钥和输入不进入日志或公开错误。
- 仅接受有大小及像素限制的 base64 PNG；不请求上游返回的任意 URL。单张最大 15 MiB。结果暂存 PostgreSQL 二进制列，接口验证所有者，响应禁止缓存；删除结果实际清除图片字节并保留扣分凭证。批量正式运营前应迁移到私有对象存储并制定保留周期。
- 系统设置可独立停用该工具、设置单次积分；账号分组在工具管理中选择。
